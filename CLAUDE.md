# Chess Battler

Мобильная 2D-игра: шахматный автобатлер с асинхронным PvP.

## Концепция

- Юниты ходят и бьют по шахматным шаблонам. Семьи:
  - **Легион** — пешки,
  - **Всадники** — кони,
  - **Мистики** — слоны,
  - **Стражи** — ладьи.
- Поле **5×6** (портрет, 5 колонок × 6 рядов). У каждой стороны 3 ряда.
- Бой идёт по **тактам** (максимум 30). В такт каждая живая фигура делает одно действие
  в порядке инициативы: бьёт врага в своей зоне атаки или ходит по шаблону к ближайшему врагу.
- **Толчки** — главная изюминка: удар сдвигает цель, столкновение с фигурой или краем поля
  наносит урон обоим участникам, возможны цепочки.
- Бой **полностью детерминирован**. Один и тот же код работает в клиенте, на сервере
  (проверка боёв) и в ботах. Seed-RNG используется только для магазина.

## Стек

TypeScript (strict), pnpm workspaces, Vitest, ESLint (flat config) + Prettier,
Vite + PixiJS v8, Supabase (пока только аналитика). Позже: Capacitor (iOS/Android).

Дизайн-документ фигур, синергий и экономики — «Фигуры, синергии и экономика забега (v0.1)»
(у пользователя; в репозитории его нет). Числа в content взяты из него один в один.

## Структура

```
packages/sim      — правила боя и забега (магазин, слияние, раунды). БЕЗ зависимостей.
packages/content  — данные: 16 фигур, синергии, RUN_CONFIG, демо-армии. Зависит от sim.
packages/bots     — армии-«призраки» под раунд и скрипт баланса. Зависит от sim и content.
apps/client       — Vite + PixiJS: забег (магазин, расстановка) и проигрывание боя.
supabase/         — SQL-миграции (таблица аналитики); применяются вручную в SQL Editor.
```

Библиотечные пакеты отдают исходники TS напрямую (`exports` → `src/index.ts`),
отдельной сборки у них нет — их собирает потребитель (Vite, Vitest, позже сервер).

## Команды

```bash
pnpm install
pnpm dev          # клиент на http://localhost:5173
pnpm test         # все тесты (Vitest)
pnpm lint         # ESLint
pnpm format       # Prettier --write (format:check — проверка)
pnpm typecheck    # tsc --noEmit во всех пакетах
pnpm build        # сборка клиента
pnpm check        # всё, что гоняет CI: format:check + lint + typecheck + test + build
pnpm balance      # 10 000 боёв «бот против бота» (--battles N --seed S --json файл)
```

Локальный Supabase (Docker, минимальный набор сервисов: база, Auth, REST, Edge Functions,
почтовый ящик Mailpit для писем со ссылками — http://127.0.0.1:54324):

```bash
pnpm supabase:start   # поднять стек и применить supabase/migrations
pnpm supabase:stop    # остановить (данные сохраняются)
pnpm tg:dev           # Telegram Mini App на локальном стеке через туннели cloudflared
```

`pnpm dev` ходит в локальный стек (`apps/client/.env.development`), прод-сборка — в облако
(`apps/client/.env`, вход там выключен `VITE_AUTH_ENABLED=0` до настройки облака).

Деплой: каждый push в `main` → `.github/workflows/deploy.yml` → GitHub Pages
(https://nikolay-inc.github.io/chess-battler/). Сборка с `base: './'`.

Перед завершением задачи прогоняй `pnpm check`.

## Правила боя (текущая реализация, packages/sim)

Координаты: `x` 0..4 слева направо, `y` 0..5 снизу вверх (с точки зрения стороны A).
Сторона **A** владеет рядами 0–2 и идёт вверх (+y), сторона **B** — рядами 3–5 и идёт вниз.
Армии задаются в **локальных** координатах стороны (`y=0` — задний ряд); для B они
поворачиваются на 180° (`placeArmy`).

- **Шаблоны** (`Pattern`): набор направлений + `slide` (луч, блокируется первой фигурой) +
  `range`. Смещения записаны относительно «вперёд» своей стороны (для B зеркалятся по y).
  Прыжки (конь) не блокируются.
- **Порядок такта**: инициатива по убыванию. При равной инициативе стороны чередуются,
  начиная со стороны с приоритетом (нечётный такт — A, чётный — B); внутри стороны —
  передний ряд раньше, затем слева направо (в локальных координатах).
  Фигура, убитая раньше своей очереди, не ходит. Сдвинутая толчком — действует с новой клетки.
- **Действие**: если в зоне атаки есть враг — удар (цель: меньше HP → ближе → порядок клеток).
  Иначе, если фигуру держит под ударом враг, — **стоит** (против погони разных шаблонов).
  Иначе ход по шаблону: клетка с минимальным числом ходов (BFS) до позиции, откуда можно
  ударить (0 — ударит на следующем такте). Если реального пути нет (закрыли свои) — оценка,
  где свои проходимы: шаг, только если сокращает её, иначе ждёт у прохода. Если пути нет и
  так — клетка, строго уменьшающая манхэттен до ближайшего врага; иначе ждёт.
- **Буря** (`Rules.storm`): с 15-го такта в начале каждого такта все фигуры получают ещё
  +1 ATK (накапливается), событие `storm`. Оставшиеся таймауты — бои без контакта
  (например, слоны на клетках разного цвета), Буря их не лечит.
- **Атака**: урон `atk`. Если цель выжила — толчок силой `push` в направлении удара
  (знак доминирующей оси; для диагонали — диагональ).
- **Толчок**: цель сдвигается по клетке, сила тратится на каждый шаг.
  Край поля → цель получает `collisionDamage`, стоп.
  Фигура на пути (любой стороны) → обе получают `collisionDamage`, цель стоит, а задетая
  фигура толкается дальше с силой `power - 1` (цепочка; глубина ограничена силой толчка).
  Фигура с HP 0 убирается с поля сразу (событие `death`) и дальше по цепочке не передаёт толчок.
  Урон при столкновении — сначала толкаемому, затем задетому.
  В логе у `push`/`collision` есть `depth`: 0 — толчок от удара, 1+ — звено цепочки.
- **Конец боя**: одна сторона уничтожена → победа другой; обе одновременно → ничья.
  По истечении `maxTicks` побеждает сторона с большей суммой оставшихся HP, иначе ничья.
- **Броня**: урон атаки `max(1, atk − armor)`; столкновения броня не снижает. **Щит**
  поглощает любой урон первым. **Оглушение** — пропуск следующего действия (не суммируется).
  **pushResist** уменьшает силу любого толчка по фигуре.
- **Способности** (`Ability`, данные в content) и **синергии семей** (`SynergyDef`, на 2 и 4
  фигуры, по копиям на поле, считаются в начале боя) интерпретирует sim. Ауры пересчитываются
  в начале каждого такта. Числа способностей ★-масштабируются (`Rules.stars`, целые десятые,
  округление половины вверх).
- Порядок триггеров: battleStart (Клич, затем Предвидение) → в начале такта ауры, затем
  Благословение → действия; после каждого действия — проверка Повышения.
- Параметры правил — `DEFAULT_RULES` (`maxTicks: 30`, `collisionDamage: 2`, множители звёзд).
- **Итоги** (`analyzeBattle`): выжившие по сторонам и «лучший момент» — удар с максимумом
  очков `урон врагам + 5 × убийства + 3 × (длина цепочки − 1)`, при равенстве — более ранний.

## Забег (packages/sim/src/run.ts)

- `RunState` — только JSON (сохраняется как есть), меняется чистым `applyAction`.
  ГПСЧ магазина живёт в состоянии: seed + лог действий воспроизводят забег целиком.
- Ничья не отнимает жизнь и не считается победой. При полной скамейке покупка разрешена,
  только если сразу сливается. Слитая фигура остаётся на месте первой копии (поле важнее).
- Соперник раунда — `generateGhost({ round, difficulty, seed: roundSeed(state) })`.
  В раундах 1–2 (`weakRounds`) призрак слабее: на 1 фигуру меньше лимита и без ★2.
  Итог раунда (`roundEnd`) фиксируется **до** анимации боя — перезагрузка не даёт переиграть.

## Клиент: стиль и навигация

- **Весь визуальный стиль — в `apps/client/src/theme/tokens.ts`** (цвета, отступы, радиусы,
  шрифты, размеры, тени, длительности). `applyTokens()` пишет CSS-переменные (`--color-*`,
  для цветов ещё `--color-*-rgb` → `rgb(var(--color-accent-rgb) / 0.2)`), Pixi берёт цвета
  через `px('token')`. Цвета напрямую в `style.css` запрещены — это проверяет тест токенов.
- Экраны: Главная, Забег (`play`), Коллекция, Магазин, Профиль, Настройки — секции
  `[data-screen]` в `index.html`, видимость по `body[data-route]`. Роутер на `#/…`
  (`router.ts`), экраны — `src/screens/*`. На экране забега панель вкладок скрыта,
  «Назад» ведёт на главную (в бою скрыта). При входе на забег canvas пересчитывается явно.
- Настройки (`settings.ts`) — localStorage с разбором битых значений (и `profiles.settings`
  после входа); скорость боя по умолчанию применяется в начале каждого боя, язык — сразу,
  звук и вибрация — к эффектам боя и магазина. Музыка пока только сохраняется.

## Локализация (ru, uk, bg, en)

- Тексты контента (семьи, названия и описания фигур и синергий) — `packages/content/locales/*.json`.
  Числа в описаниях — плейсхолдеры `{amount}`, их значения дают `unitTextParams(def)` /
  `synergyTextParams(effect)`; в карточке передаётся `starScaledDef`, поэтому числа со звёздами.
- Строки интерфейса — `apps/client/src/i18n/*.json`, вызов `t('home.play', { … })` (ключи
  типизированы по `ru.json`). Множественное число — объект форм `one/few/many/other`,
  выбор через `Intl.PluralRules`, число — параметр `n`. Разметка — `data-i18n` / `data-i18n-aria`.
- Язык: настройки → Telegram `language_code` → `navigator.languages` → английский.
  Смена языка перерисовывает текущий экран, забег и надписи Pixi (`relabel()`).
- Тесты: во всех языках те же ключи, плейсхолдеры и нужные формы множественного числа;
  ключи `data-i18n` существуют; в коде клиента нет кириллицы вне комментариев.
- uk/bg/en написаны не носителями — перед релизом отдать на вычитку.

## Аккаунт и профиль (подэтап C)

- `account.ts` — Supabase Auth: гость (`signInAnonymously`) по умолчанию; привязка email
  (`updateUser`, письмо подтверждения обязательно) и Google (`linkIdentity`) **сохраняют id**,
  поэтому прогресс гостя остаётся; вход в существующий аккаунт — magic link
  (`signInWithOtp`, `shouldCreateUser: false`); выход → новый гость; удаление —
  Edge Function `supabase/functions/delete-account` (service role: аналитика по `user_id`,
  затем пользователь Auth, профиль и история — каскадом).
- Адрес возврата из писем/OAuth — `/?auth=callback` **без hash-маршрута**: Supabase дописывает
  токены в hash, второй `#` их ломает. После входа клиент открывает `#/profile`.
- `profile-store.ts` — профиль (ник, аватар), история забегов (локальный кэш + `run_history`,
  неотправленное доотправляется), статистика, синхронизация настроек с `profiles.settings`
  (при входе на новом устройстве серверные настройки главнее). Кэш другого владельца сбрасывается.
- Google: провайдер в `supabase/config.toml` выключен до client id/secret (env-переменные,
  redirect URI локально — `http://127.0.0.1:54321/auth/v1/callback`). Apple — заготовка.
- Звук — синтез WebAudio (`sfx.ts`, без ассетов), вибрация — `navigator.vibrate`; музыки пока нет.

## Покупки (подэтап D)

- Только косметика: скины доски, рамки своих фигур, эффекта толчка (`packages/content/src/cosmetics.ts`).
  Меняют лишь отрисовку (`board.applySkin`, `setPlayerFrame`, `setPushFx`) — sim их не видит.
- Сервер — источник правды: `products` (тест сверяет с каталогом content), `purchases`
  (клиент только читает свои; записывает сервер после проверки платежа, повтор платежа
  отсекает `unique (provider, provider_charge_id)`), `profiles.equipped` — триггер не даёт
  надеть некупленное. Удаление аккаунта удаляет и покупки (каскад).
- `PaymentProvider` (`apps/client/src/payments/provider.ts`): Telegram Stars (клиент:
  `stars-invoice` → `WebApp.openInvoice`; сервер — см. «Telegram Mini App»), тестовая оплата
  `DevProvider` (только dev + Edge Function `dev-purchase`, секрет `ALLOW_DEV_PURCHASES`
  задан лишь в локальном `config.toml`), App Store / Google Play / Stripe — заглушки.
  Выбирается первый доступный (`pickProvider`).

## Telegram Mini App (подэтап E)

- Клиент (`apps/client/src/telegram.ts`): SDK `telegram-web-app.js` грузится, только если
  в адресе есть параметры запуска `tgWebApp*`. Внутри Telegram: `ready`/`expand`,
  `disableVerticalSwipes`, тема Telegram поверх токенов (`setColorOverrides`, `themeChanged`),
  `BackButton` вне главной (в бою не срабатывает), вибрация через `HapticFeedback`,
  отступы — `--tg-safe-area-inset-*` / `--tg-content-safe-area-inset-*` (переменные SDK,
  тест стилей их разрешает).
- Вход: `telegram-auth` проверяет подпись initData (HMAC, ключ `HMAC("WebAppData", токен)`)
  и `auth_date` (≤ суток), находит пользователя по `telegram_accounts`; если связи нет и
  вызывающий — гость, **гость становится аккаунтом Telegram с тем же id** (прогресс цел),
  иначе создаётся новый. Email технический (`tg-<id>@telegram.invalid`); клиент получает
  сессию через `verifyOtp(token_hash)`. Признак аккаунта Telegram — `user_metadata.telegram_id`
  (`app_metadata.provider` Auth перезаписывает на `email`). «Выйти» для такого аккаунта скрыт.
- Stars: `stars-invoice` (JWT, товар из `products`, не куплен ли) → `createInvoiceLink` в XTR
  (`provider_token: ''`); `telegram-webhook` (заголовок `X-Telegram-Bot-Api-Secret-Token`):
  `pre_checkout_query` — сверка товара, цены, валюты; `successful_payment` — запись в
  `purchases` (`telegram_payment_charge_id`, повтор отсекает unique); `/start` — кнопка Mini App.
- Секреты (`supabase/.env`, в git не попадает; `supabase start` подставляет их в
  `[edge_runtime.secrets]`): `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` (генерирует
  `tg:dev`). `TELEGRAM_TEST_ENV=1` — тестовое окружение Telegram (Bot API `/bot<token>/test/…`).
  Токен добавлен после старта стека → `pnpm supabase:stop && pnpm supabase:start`.
- `pnpm tg:dev` (`scripts/tg-dev.mjs`): туннели к Supabase и к Vite (порт 5174, `TG_DEV_PORT`),
  `setWebhook` + кнопка меню «Play», Vite с `VITE_SUPABASE_URL` = туннель. Ctrl+C гасит всё.
  `supabase functions serve` не использовать при поднятом стеке: при выходе он удаляет
  контейнер функций стека (до перезапуска стека функции отвечают 503).

## Клиент: проигрывание боя

- Лог режется на такты и действия (`timeline.ts`). Действия такта идут каскадом
  (`staggerMs`), но действие с общими фигурами ждёт окончания более ранних — иначе
  анимации одной фигуры перепутаются. Такт не короче `PACING.minTickMs` (0,6 с на ×1).
- Позиция фигуры = `base` (клетка) + независимые смещения `lunge`/`shake`.
- Клетки подсветки считает sim (`moveTargets`, `attackZone`) — не дублировать в клиенте.
- Перетаскивание — pointer capture на canvas (мышь и тач одним кодом); продажа — бросок
  на DOM-магазин. Hit-test Pixi опирается на мировые координаты, обновляемые при отрисовке.
- В dev-сборке есть `window.__debug` (`app`, `player`, `game`, `board`, `analytics`): можно остановить
  `app.ticker` и крутить `app.ticker.update(t)` вручную — так замеряется темп и проверяется,
  что после проигрывания доска совпадает с `result.final`, даже если вкладка скрыта.

## Правила разработки

- **Детерминизм sim — святое.** В `packages/sim` запрещены `Math.random`, `Date`,
  `performance`, таймеры, обход `Object.keys` объектов-словарей для порядка действий,
  float-арифметика для игровой логики (только целые). Все сортировки — с полным
  tie-break. ESLint это частично проверяет; остальное — на ревью.
- Любое изменение правил, меняющее исход боя, — осознанное: обнови golden-снапшот
  в `packages/sim/test/determinism.test.ts` (`pnpm test -u`) и раздел «Правила боя» выше.
- Sim — чистые функции: вход (`BattleSetup`, `Rules`) → `BattleResult` с полным логом событий.
  Никаких синглтонов и глобального состояния.
- Клиент только **проигрывает** лог событий; игровую логику в клиенте не дублировать.
- Новая механика sim → тесты в `packages/sim/test` на собственных тестовых фигурах
  (не из content), чтобы тесты правил не ломались от баланса.
- Данные фигур (баланс) — только в `packages/content`. Идентификаторы — латиница
  (`legionnaire`). **Никаких текстов в данных и коде клиента** — см. «Локализация».
- Код и идентификаторы — на английском, комментарии и документация — можно по-русски.
- Аналитика (`apps/client/src/analytics.ts`, строки — `telemetry.ts`): события `run_start`,
  `round_end` (с `reason`), `run_end` в `analytics_events`; снимок армии после каждого раунда в
  `army_snapshots`; опрос конца забега в `run_feedback`. Во всех строках `device_id` (анонимный
  id игрока), `session_id` (новая сессия после 30 мин тишины) и `app_version`. Supabase REST,
  publishable-ключ в `apps/client/.env`, RLS — только вставка. Отправляется только из
  прод-сборки; в dev — в консоль. Метрики проверки 2 — представления `pt2_*` (см. миграции).
