# Chess Battler

Мобильная 2D-игра: шахматный автобатлер с асинхронным PvP.

## Концепция

- Юниты ходят и бьют по шахматным шаблонам. Семьи:
  - **Легион** — пешки,
  - **Всадники** — кони,
  - **Мистики** — слоны,
  - **Стражи** — ладьи.
- Поле **5×6** (портрет, 5 колонок × 6 рядов). У каждой стороны 3 ряда.
- Бой идёт по **тактам** (максимум 30). В такт каждая живая фигура делает одно действие
  в порядке инициативы: бьёт врага в своей зоне атаки или ходит по шаблону к ближайшему врагу.
- **Толчки** — главная изюминка: удар сдвигает цель, столкновение с фигурой или краем поля
  наносит урон обоим участникам, возможны цепочки.
- Бой **полностью детерминирован**. Один и тот же код работает в клиенте, на сервере
  (проверка боёв) и в ботах. Seed-RNG используется только для магазина.

## Стек

TypeScript (strict), pnpm workspaces, Vitest, ESLint (flat config) + Prettier,
Vite + PixiJS v8, Supabase (пока только аналитика). Позже: Capacitor (iOS/Android).

Дизайн-документ фигур, синергий и экономики — «Фигуры, синергии и экономика забега (v0.1)»
(у пользователя; в репозитории его нет). Числа в content взяты из него один в один.

## Структура

```
packages/sim      — правила боя и забега (магазин, слияние, раунды). БЕЗ зависимостей.
packages/content  — данные: 16 фигур, синергии, RUN_CONFIG, демо-армии. Зависит от sim.
packages/bots     — армии-«призраки» под раунд и скрипт баланса. Зависит от sim и content.
apps/client       — Vite + PixiJS: забег (магазин, расстановка) и проигрывание боя.
supabase/         — SQL-миграции (таблица аналитики); применяются вручную в SQL Editor.
```

Библиотечные пакеты отдают исходники TS напрямую (`exports` → `src/index.ts`),
отдельной сборки у них нет — их собирает потребитель (Vite, Vitest, позже сервер).

## Команды

```bash
pnpm install
pnpm dev          # клиент на http://localhost:5173
pnpm test         # все тесты (Vitest)
pnpm lint         # ESLint
pnpm format       # Prettier --write (format:check — проверка)
pnpm typecheck    # tsc --noEmit во всех пакетах
pnpm build        # сборка клиента
pnpm check        # всё, что гоняет CI: format:check + lint + typecheck + test + build
pnpm balance      # 10 000 боёв «бот против бота» (--battles N --seed S --json файл)
```

Деплой: каждый push в `main` → `.github/workflows/deploy.yml` → GitHub Pages
(https://nikolay-inc.github.io/chess-battler/). Сборка с `base: './'`.

Перед завершением задачи прогоняй `pnpm check`.

## Правила боя (текущая реализация, packages/sim)

Координаты: `x` 0..4 слева направо, `y` 0..5 снизу вверх (с точки зрения стороны A).
Сторона **A** владеет рядами 0–2 и идёт вверх (+y), сторона **B** — рядами 3–5 и идёт вниз.
Армии задаются в **локальных** координатах стороны (`y=0` — задний ряд); для B они
поворачиваются на 180° (`placeArmy`).

- **Шаблоны** (`Pattern`): набор направлений + `slide` (луч, блокируется первой фигурой) +
  `range`. Смещения записаны относительно «вперёд» своей стороны (для B зеркалятся по y).
  Прыжки (конь) не блокируются.
- **Порядок такта**: инициатива по убыванию. При равной инициативе стороны чередуются,
  начиная со стороны с приоритетом (нечётный такт — A, чётный — B); внутри стороны —
  передний ряд раньше, затем слева направо (в локальных координатах).
  Фигура, убитая раньше своей очереди, не ходит. Сдвинутая толчком — действует с новой клетки.
- **Действие**: если в зоне атаки есть враг — удар (цель: меньше HP → ближе → порядок клеток).
  Иначе ход по шаблону: клетка с минимальным числом ходов (BFS) до позиции, откуда можно
  ударить; если пути нет — клетка, строго уменьшающая манхэттен до ближайшего врага; иначе ждёт.
- **Атака**: урон `atk`. Если цель выжила — толчок силой `push` в направлении удара
  (знак доминирующей оси; для диагонали — диагональ).
- **Толчок**: цель сдвигается по клетке, сила тратится на каждый шаг.
  Край поля → цель получает `collisionDamage`, стоп.
  Фигура на пути (любой стороны) → обе получают `collisionDamage`, цель стоит, а задетая
  фигура толкается дальше с силой `power - 1` (цепочка; глубина ограничена силой толчка).
  Фигура с HP 0 убирается с поля сразу (событие `death`) и дальше по цепочке не передаёт толчок.
  Урон при столкновении — сначала толкаемому, затем задетому.
  В логе у `push`/`collision` есть `depth`: 0 — толчок от удара, 1+ — звено цепочки.
- **Конец боя**: одна сторона уничтожена → победа другой; обе одновременно → ничья.
  По истечении `maxTicks` побеждает сторона с большей суммой оставшихся HP, иначе ничья.
- **Броня**: урон атаки `max(1, atk − armor)`; столкновения броня не снижает. **Щит**
  поглощает любой урон первым. **Оглушение** — пропуск следующего действия (не суммируется).
  **pushResist** уменьшает силу любого толчка по фигуре.
- **Способности** (`Ability`, данные в content) и **синергии семей** (`SynergyDef`, на 2 и 4
  фигуры, по копиям на поле, считаются в начале боя) интерпретирует sim. Ауры пересчитываются
  в начале каждого такта. Числа способностей ★-масштабируются (`Rules.stars`, целые десятые,
  округление половины вверх).
- Порядок триггеров: battleStart (Клич, затем Предвидение) → в начале такта ауры, затем
  Благословение → действия; после каждого действия — проверка Повышения.
- Параметры правил — `DEFAULT_RULES` (`maxTicks: 30`, `collisionDamage: 2`, множители звёзд).
- **Итоги** (`analyzeBattle`): выжившие по сторонам и «лучший момент» — удар с максимумом
  очков `урон врагам + 5 × убийства + 3 × (длина цепочки − 1)`, при равенстве — более ранний.

## Забег (packages/sim/src/run.ts)

- `RunState` — только JSON (сохраняется как есть), меняется чистым `applyAction`.
  ГПСЧ магазина живёт в состоянии: seed + лог действий воспроизводят забег целиком.
- Ничья не отнимает жизнь и не считается победой. При полной скамейке покупка разрешена,
  только если сразу сливается. Слитая фигура остаётся на месте первой копии (поле важнее).
- Соперник раунда — `generateGhost({ round, difficulty, seed: roundSeed(state) })`.
  Итог раунда (`roundEnd`) фиксируется **до** анимации боя — перезагрузка не даёт переиграть.

## Клиент: проигрывание боя

- Лог режется на такты и действия (`timeline.ts`). Действия такта идут каскадом
  (`staggerMs`), но действие с общими фигурами ждёт окончания более ранних — иначе
  анимации одной фигуры перепутаются. Такт не короче `PACING.minTickMs` (0,6 с на ×1).
- Позиция фигуры = `base` (клетка) + независимые смещения `lunge`/`shake`.
- Клетки подсветки считает sim (`moveTargets`, `attackZone`) — не дублировать в клиенте.
- Перетаскивание — pointer capture на canvas (мышь и тач одним кодом); продажа — бросок
  на DOM-магазин. Hit-test Pixi опирается на мировые координаты, обновляемые при отрисовке.
- В dev-сборке есть `window.__debug` (`app`, `player`, `game`, `board`, `analytics`): можно остановить
  `app.ticker` и крутить `app.ticker.update(t)` вручную — так замеряется темп и проверяется,
  что после проигрывания доска совпадает с `result.final`, даже если вкладка скрыта.

## Правила разработки

- **Детерминизм sim — святое.** В `packages/sim` запрещены `Math.random`, `Date`,
  `performance`, таймеры, обход `Object.keys` объектов-словарей для порядка действий,
  float-арифметика для игровой логики (только целые). Все сортировки — с полным
  tie-break. ESLint это частично проверяет; остальное — на ревью.
- Любое изменение правил, меняющее исход боя, — осознанное: обнови golden-снапшот
  в `packages/sim/test/determinism.test.ts` (`pnpm test -u`) и раздел «Правила боя» выше.
- Sim — чистые функции: вход (`BattleSetup`, `Rules`) → `BattleResult` с полным логом событий.
  Никаких синглтонов и глобального состояния.
- Клиент только **проигрывает** лог событий; игровую логику в клиенте не дублировать.
- Новая механика sim → тесты в `packages/sim/test` на собственных тестовых фигурах
  (не из content), чтобы тесты правил не ломались от баланса.
- Данные фигур (баланс) — только в `packages/content`. Идентификаторы — латиница
  (`legionnaire`), отображаемые имена — по-русски.
- Код и идентификаторы — на английском, комментарии и документация — можно по-русски.
- Аналитика (`apps/client/src/analytics.ts`): события `run_start`, `round_end`, `run_end` в
  `public.analytics_events` (Supabase REST, publishable-ключ в `apps/client/.env`, RLS —
  только вставка). Отправляется только из прод-сборки; в dev — в консоль.
